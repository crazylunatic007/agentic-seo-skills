# Brief template

Adapt to the team's house format. The section order below front-loads the decisions an editor
makes, so an approval or rejection happens in the first thirty seconds of reading.

---

## Header

| Field | Value |
|---|---|
| Working title | |
| Target URL | New, or the existing URL being upgraded |
| Content type | Guide, comparison, listicle, explainer, opinion |
| Primary keyword | Keyword, volume, difficulty |
| Secondary keywords | From data, not invented |
| Current ranking (if updating) | |
| Audience level | Beginner, practitioner, specialist |
| Word count guidance | A range, with the reasoning |
| Author or SME needed | |

## The decision

**Target reader** — Who specifically, and what they are trying to get done. One or two sentences,
no personas with names.

**Search intent** — What the searcher expects to find, based on what the SERP rewards.

**Core argument** — The position the page takes. If the page has no position, say why a neutral
reference page is the right call here.

**What this page does that the ranking pages do not** — Specific. "More comprehensive" and "better
written" are not answers. Original data, a real worked example, a practitioner's perspective, an
opinion the category avoids, a format nobody has tried, or access to information the competitors
lack.

If this section is weak, stop and say so before the brief goes further.

## SERP evidence

| Field | Value |
|---|---|
| Featured snippet present | Yes / No, and what holds it |
| AI Overview present | Yes / No, and which sub-topics it covers |
| Dominant format in the top 10 | |
| Average length of top results | |
| Domains ranking repeatedly across the topic | |
| Notable gaps across all ranking pages | |

Report only what was observed. If a check could not be run, write that rather than leaving it blank.

## Coverage and cannibalization

| Existing URL | Overlapping queries | Recommendation |
|---|---|---|

Recommendations: keep separate, consolidate into the new page, update the existing page instead of
creating a new one, or redirect.

If an existing page already covers the intent, recommending an update rather than a new page is
usually the right answer, and is the outcome most briefs avoid because a new page feels like more
progress.

## Structure

For each proposed section: the heading, one to three lines of direction, and the questions it must
answer. Give the writer direction and room to make choices. A brief that specifies every sentence
produces a writer who stops thinking.

Mark sections as ADD for upgrades, or KEEP / REWRITE / MERGE / CUT / ADD for rewrites, so the
writer knows what to preserve.

## Questions the page must answer

Pulled from question-type queries and from the gaps in ranking pages. These are the acceptance
criteria for the draft.

## Evidence required

Data, screenshots, examples, quotes, or original research. Name who or what supplies each one. A
brief that asks for original data without saying where it comes from is a brief that ships without it.

## Internal links

| Link to | From which section | Why it helps the reader |
|---|---|---|

Verify every URL exists before including it. Never guess a URL.

## Product integration

Where the product genuinely belongs in the reader's task, and where it does not. Being explicit
about where not to mention it is what keeps the page credible.

## Meta

Title tag and meta description, or leave blank for the writer with a note on the angle they should
carry.
